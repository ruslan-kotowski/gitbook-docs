To ensure that your users can access Miro securely, configure Single sign-on (SSO).

When a user submits their credentials to sign into Miro, Miro sends a request to your identity provider (IdP) to validate their credentials. If your IdP confirms their identity, then the user can access Miro.

Your Enterprise subscription can leverage any identity provider, like Entra ID, Google SSO, and Okta.

## How to configure Single sign-on

The following procedure explains how to configure SSO in Miro.

#### Prerequisites

Ensure that you complete the following prerequisites:

- Configure your identity provider (IdP) for Miro.
  The following list provides setup instructions for supported identity providers:
  - [AWS](../../../security-integrations/single-sign-on-sso/04-how-to-configure-aws-sso.md)
  - [Okta](../../../security-integrations/single-sign-on-sso/07-how-to-configure-okta-sso.md)
  - [Google](../../../security-integrations/single-sign-on-sso/06-how-to-configure-google-sso.md)
  - [Entra ID](../../../security-integrations/single-sign-on-sso/05-how-to-configure-entra-id-sso.md)
  - [OneLogin](../../../security-integrations/single-sign-on-sso/08-how-to-configure-onelogin-sso.md)
  - [Auth0](../../../security-integrations/single-sign-on-sso/03-how-to-сonfigure-auth0-sso.md)
  - [ADFS](../../../security-integrations/single-sign-on-sso/02-how-to-configure-adfs-sso.md)
    > For Miro service-provider (SP) metadata that your IdP may require, see [Miro metadata for Single sign-on configuration](../../../enterprise-guard/appendix/01-miro-metadata-for-single-sign-on-configuration.md).
- (Optional) Create a break glass user.
  A break glass user is an account outside the SSO domain, like break.glass@gmail.com, with high privileges. In an emergency, like a service outage or cyber attack, your break glass user supports recovery. To learn more about privileged break glass users, see [Break glass privileged accounts for disaster recovery](https://delinea.com/blog/break-glass-accounts).

#### Procedure

Follow these steps:

1. Go to **Admin console**.
2. Select **Authentication**.
3. Select **+ Add identity provider**.
   The **Add identity provider** menu opens.
4. Follow the on-screen instructions.
   > ✏️ Your IdP issues your public **Key x.509 Certificate**.
5. (Optional) To select a default team for new users to join when they register, known as Just-in-time provisioning, tick **Automatically add all newly registered users from the listed domains to your Enterprise account**.
6. (Optional) To sync user profile photos from your IdP, tick **Sync user profile photos from IDP**.
7. (Optional) To always require authentication, tick **Always require authentication**.

   You have successfully configured SSO in Miro.
