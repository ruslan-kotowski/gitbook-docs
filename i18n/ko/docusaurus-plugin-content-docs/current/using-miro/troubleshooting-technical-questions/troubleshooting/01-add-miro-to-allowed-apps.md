가끔 Miro 기능이 허용되지 않을 때 성능에 문제가 발생할 수 있습니다. 이는 네트워크 연결이나 사용 환경에 적용된 문제나 제약사항 때문에 발생할 수 있습니다. 다음 기사는 이러한 문제의 가장 일반적인 원인을 나열합니다.

## 웹소켓

Miro 애플리케이션 - 특히 *보드* 페이지 - 는 웹소켓 연결이 필요합니다. 대시보드와 설정 페이지는 정상적으로 열리지만 보드를 여는 데 문제가 있다면, 이는 연결이 웹소켓을 지원하지 않기 때문일 수 있습니다.

연결을 테스트하려면 [이 웹사이트](http://websocketstest.com)를 여세요.

웹소켓이 인식되면 다음 메시지가 표시됩니다:

![wensocket_connection.jpg](../../../../../../../docs/using-miro/troubleshooting-technical-questions/troubleshooting/images/21020264610066_wensocket%20connection.jpg)

결과가 다르게 나타난다면, 이는 네트워크에서 웹소켓 연결을 차단하고 있을 가능성이 높습니다. 이 경우 다음을 시도해 보세요:

- 다른 네트워크 연결 사용
- VPN 사용 또는 끄기
- 기업 네트워크를 사용할 경우, 네트워크 관리자에게 연락해 포트 80과 443(SSL)의 WebSocket 연결을 활성화하도록 요청하세요. 보안상의 이유로 기업 네트워크 내에서 닫히거나 필터링될 수 있습니다. 연결을 설정하려면 Miro 주소에 대한 이 포트들이 열려 있어야 합니다(아래 "방화벽을 사용하는 경우" 섹션에서 주소를 참조하세요)

Websocket이 올바르게 식별되었지만 여전히 연결에 문제가 있는 경우, [Miro 지원](https://help.miro.com/hc/requests/new?referer=help-center-article)에 문의하세요.

### Miro 도메인 허용 목록

보안 네트워크를 사용하는 조직은 모든 Miro 도메인을 허용해야 합니다. 허용해야 하는 도메인의 전체 목록은 [Miro 도메인](../technical-guidelines/07-miro-domains-reference.md)을 참조하세요.

## 프록시를 사용하는 경우

Miro를 우회할 수 있도록 설정해 주시기 바랍니다. 다음 사양이 도움이 될 것입니다.

- 프록시 서버는 WebSocket 연결(HTTP/2)을 지원해야 합니다.
- 프록시 HTTP 버전은 1.1로 설정해야 합니다.
- 소스 IP/호스트: 위의 NAT IP 참조(Atlassian 통합 전용).
- 소스 포트: **80.** 80은 사용자가 HTTP를 통해 Miro에 접근할 때 HTTPS로 유도하기 위해 사용되므로 차단하지 않는 것이 좋습니다.
- 대상 포트: **443 (SSL).**443은 HTTPS에 사용됩니다.
- 프로토콜: HTTPS
- TLS: 1.2. (우리는 AWS에 호스팅되어 있으며 AWS 보안 정책을 사용합니다. AWS 및 모든 플러그인 파트너가 1.3을 지원하면 저희도 함께 이전할 수 있습니다).
- 프록시 서버의 타임아웃 값을 연장해야 합니다. 시스템이 접속하는 데 보통 60-90초가 걸립니다. 120-180초로 연장하는 것이 가장 좋습니다.
- 프록시 서버는 요청과 응답 헤더를 잘라내지 않아야 합니다. *Upgrade* 및 *Connection* 헤더가 클라이언트에 의해 프록시되는지 확인하세요.
