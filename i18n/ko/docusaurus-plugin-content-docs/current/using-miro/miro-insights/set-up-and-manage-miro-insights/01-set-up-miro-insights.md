귀하의 도구를 Miro Insights에 연결하는 것은 실제 가치를 얻기 위한 중요한 첫걸음입니다. Miro Insights는 통합을 통해 귀하의 시스템 전반에서 고객 피드백 및 관련 데이터를 자동으로 가져올 수 있습니다. 이 가이드는 이러한 연결을 활성화할 회사 관리자를 위한 것입니다.

설정 후 Miro Insights를 사용하고자 하는 팀 구성원은 [Miro Insights 사용](../../miro-insights/use-miro-insights)에 관한 기사를 참조하십시오.

## 사전 조건

Miro Insights 통합을 설정하려면 다음 요구 사항을 충족해야 합니다:

- Miro의 **회사 관리자**여야 합니다.
- **외부 플랫폼에 대한 관리자 또는 API 액세스** 권한이 있어야 합니다.

:::note
**Miro 플랜에 Miro Insights**가 포함되어 있는지 확인하세요. Miro Insights가 애드온이거나 제한된 릴리스인 경우, 계정이 적합해야 합니다. 또한, 일부 통합은 외부 소프트웨어의 특정 에디션이 필요할 수 있습니다. 예를 들어, 일부 CRM API 액세스는 상위 플랜에서 사용할 수 있습니다.
:::

## 데이터 소스 준비하기

Miro Insights와 데이터 소스를 연결하기 전에, 데이터를 준비하고 명확한 분류 체계를 확립하는 것이 중요합니다. 이러한 준비는 플랫폼으로부터 가장 정확하고 실질적인 인사이트를 얻는 데 도움이 됩니다.

### 데이터 정제 및 최적화

Miro Insights와 데이터를 동기화하기 전에 데이터 소스를 정제하고 최적화하세요:

- 중복 및 오래된 항목을 제거하세요.
- 불일치하거나 관련성이 없는 피드백을 정리하세요.
- 소스 시스템에서 데이터 품질을 보장하세요.
- 데이터의 주요 불일치나 결함을 미리 해결하세요.

### 분류 체계 수립

Miro Insights는 기본적인 AI 생성 카테고리를 제공하지만, 배포 전에 표준화된 분류 체계를 정의하는 것이 좋습니다. 이는 일관성을 보장하고 인사이트의 품질을 초기부터 향상시킵니다.

다음과 같은 표준 카테고리를 고려해보세요:

- 기능 요청
- 버그
- UX 페인 포인트
- 고객 세그먼트
- 우선순위 레벨
- 비즈니스 유닛
- 전략적 이니셔티브

분류 체계에 대한 모범 사례:

- 팀의 언어와 맞는 용어를 사용하세요.
- 각 범주 사용에 대한 명확한 지침을 만드세요.
- 팀과 함께 분류 체계를 공유하여 일관성 있는 사용을 보장하세요.
- 정기적으로 범주를 검토하고 필요한 경우 조정하세요.
- 전략적 이니셔티브와 OKR에 매핑을 고려하세요.

:::tip
분류 체계를 정의하는 데 Miro Insights 지원에 문의하세요. 이들은 귀사의 산업 내 다른 고객의 사례와 모범 사례를 제공할 수 있습니다.
:::

## 통합 연결

데이터가 준비되면 통합을 연결할 수 있습니다. Miro Insights는 CRM, 지원, 영업 통화, 프로젝트 관리, 채팅 플랫폼 등 다양한 인기 툴을 지원합니다.

**통합 & 스마트 플로** 설정 탭에서 연결된 모든 통합을 보고 관리할 수 있습니다. 각 통합은 연결 상태, 구성 또는 연결 해제 옵션과 함께 나열됩니다.

통합을 연결하려면:

1. **Miro Insights** 앱에서 왼쪽 사이드바 상단의 **설정** 아이콘을 선택합니다.
2. **설정** 패널에서 **통합 & 스마트 플로** 탭으로 이동합니다.
3. 추가할 통합 옆의 **연결** 을 선택합니다.
4. **접근 권한 승인**. 팝업 창이 나타나 Miro Insights가 해당 도구에 대한 접근 권한을 승인하도록 요청합니다.
   이는 일반적으로 외부 서비스에 로그인하고 권한을 부여하는 과정을 포함합니다. 예를 들어 Salesforce를 연결할 때는 Salesforce 관리자 계정으로 로그인하여 통합을 승인해야 합니다. Slack의 경우 워크스페이스를 선택하고 Miro Insights Slack 앱에 권한을 부여합니다. 각 단계의 화면 지시에 따라 진행하세요.
5. **가져오기 설정 구성**. 연결되면 통합은 "연결됨"으로 표시되며 추가 설정 옵션이 나타납니다. 여기서 설정할 수 있는 항목은 다음과 같습니다.
   - **가져올 대화 선택**: Gong이나 Zendesk와 같은 대화 기반 소스에서는 날짜를 선택할 수 있습니다. 이렇게 하면 원하지 않는 한 오래된 데이터를 가져오는 것을 방지할 수 있습니다.
   - **자동 가져오기 규칙**: 새로운 항목이 자동으로 가져와질지 여부를 조정할 수 있습니다. 이를 활성화하면 새로운 전화나 티켓이 지속적으로 들어옵니다. 비활성화하면 항목을 수동으로 또는 선택적으로 가져올 수 있습니다.
   - **AI가 요청을 감지할 경우**: 일부 소스는 AI 감지 신뢰도로 필터링할 수 있습니다.
   - **이슈 감지**: Miro Insights는 고객 피드백에서 이슈를 자동으로 식별하고 추출합니다. 이슈에는 사용성 문제, 성능 문제, 보안 문제 등이 포함될 수 있습니다.

다른 옵션은 통합에 따라 달라질 수 있습니다. 예를 들어, Jira에서 기능을 가져올 프로젝트를 선택하거나 맞춤형 필드를 매핑할 수 있습니다.

### AI 필터링

일부 통합에서는 **AI 감지로 필터링**할 수 있습니다. 이는 Insights가 통화 기록을 스캔하고 제품 요청이 언급되었다고 확신할 때만 피드백 항목을 생성한다는 것을 의미합니다. 이는 불필요한 대화에서 발생하는 소음을 줄여줍니다. 신뢰도 기준을 조정하거나 이 기능을 끄고 모든 것을 가져올 수 있습니다.

### 태그 또는 필드 필터

Zendesk와 같은 도구에서는 “feature_request”와 같은 태그를 지정할 수 있습니다. 그런 다음 해당 태그가 있는 티켓만 수집됩니다. Jira에서는 특정 프로젝트나 이슈 유형을 기능으로 가져오도록 선택할 수 있습니다.

### 이슈 동기화

Jira와 같은 프로젝트 도구에서는 필드를 매핑할 수 있는 옵션이 있을 수 있습니다. 위의 스크린샷은 "기능의 금액 값을 맞춤형 필드로 푸시"하는 예를 보여주며, 이를 통해 Miro Insights에서 계산된 금액 영향을 Jira의 사용자 지정 필드에 채우고 엔지니어링으로 다시 연결할 수 있습니다. 이 단계는 필수 사항은 아니지만 강력할 수 있습니다.

모든 관련 시스템을 연결하세요. 최소 하나의 CRM과 하나의 지원 또는 피드백 소스를 연결하는 것이 좋습니다. 이렇게 하면 계정 컨텍스트와 원시 피드백을 모두 얻을 수 있습니다. 나중에 더 추가할 수 있습니다.

모든 설정을 완료하면 통합 설정이 Miro Insights에 성공적으로 연결됩니다. 시스템은 데이터를 동기화하기 시작합니다. 초기 동기화는 많은 양의 과거 데이터가 있는 경우 약간의 시간이 소요될 수 있습니다 (각 통합 옆에서 마지막 동기화된 타임스탬프를 볼 수 있습니다). 동기화 상태는 통합 목록에서 모니터링할 수 있으며, 마지막 동기화된 시간을 보여주고 필요한 경우 연결 끊기 옵션을 제공합니다.

## 항목 수동으로 가져오기

기능 및 피드백 항목을 CSV 파일을 사용하여 вруч으로 가져올 수도 있습니다. 이는 일회성 가져오기나 다른 소스에서 받은 기능 요청이나 피드백 목록의 경우 유용합니다.

CSV를 통해 기능을 가져오려면 다음을 수행하십시오:

1. Miro Insights에서 **백로그** 보기를 엽니다.
2. 오른쪽 상단의 **가져오기** 버튼을 클릭합니다.
3. **CSV 업로드**를 선택합니다.
4. CSV 데이터 소스에서 Miro Insights의 속성과 가장 일치하는 열을 선택합니다.
5. **기능 가져오기**를 선택하여 프로세스를 완료합니다.

가져온 기능들은 이제 [백로그](../../tools/use-miro-insights/05-backlog.md) 섹션에 나타납니다.

피드백 항목을 CSV를 통해 가져오려면:

1. Miro Insights에서 **피드백** 보기를 엽니다.
2. 오른쪽 위의 **가져오기** 버튼을 클릭합니다.
3. **CSV 업로드**를 선택합니다.
4. CSV의 열을 Miro Insights의 피드백 속성(예: 제목, 설명, 출처)과 매핑합니다.
5. **피드백 가져오기** 를 선택하여 프로세스를 완료합니다.

가져온 피드백 항목은 이제 [피드백](../../tools/use-miro-insights/07-feedback.md) 섹션에 나타납니다.

## 지원되지 않는 도구를 Zapier로 연결

직접 지원되지 않는 도구가 있다면, 종종 [Zapier](http://zapier.com/)를 사용하여 데이터를 Miro Insights로 전달할 수 있습니다. 예를 들어, 다음과 같은 Zapier 워크플로를 만들 수 있습니다. Google Form이 제출되거나 맞춤형 데이터베이스에 새 항목이 나타날 때 Miro Insights에 피드백 항목을 생성합니다.

자세한 단계는 [Miro Insights와 Zapier 사용하기](../../miro-insights/set-up-and-manage-miro-insights/03-connect-tools-with-zapier.md) 기사를 참조하세요.

## 추가 단계

통합 연결 후, 모든 것이 제대로 설정되었는지 확인하기 위한 몇 가지 선택적 단계를 수행할 수 있습니다:

### 기능 가져오기 또는 확인

Jira와 같은 작업 추적기를 연결한 경우, Miro Insights의 백로그에서 기존 기능이나 에픽이 나타났는지 확인하십시오. 나타나지 않은 경우, 백로그 보기에서 가져오기 버튼을 사용하여 CSV를 업로드하거나 Jira로부터 데이터를 가져올 수 있습니다. 각 가져온 기능이 명확한 제목과 설명을 가지고 있는지 확인하십시오. AI는 해당 텍스트에 의존하여 관련 피드백을 일치시킵니다.

### Slack 명령어 설정 또는 이메일 전달 설정

Slack을 추가한 경우, 팀에게 인사이트로 메시지를 보내는 방법을 알려주십시오. 예를 들어, 메시지를 우클릭하고 "Miro Insights로 보내기"를 선택합니다.

이메일이나 다른 채널의 경우 전달을 구성할 수 있습니다. 일부 팀은 Intercom과 같은 도구나 가져오기를 위한 Zapier 훅에 자동 전송되는 특정 이메일 주소를 설정하기도 합니다.

> **팁**: 통합 설정을 주기적으로 검토하는 것이 좋습니다. 예를 들어, 특정 소스에서 사소한 피드백이 너무 많이 들어온다면 필터를 강화하거나 AI 신뢰도를 높이세요. 반대로 기대한 데이터를 놓치고 있다면 통합이 적절한 범위(예: 올바른 프로젝트나 태그)로 연결되어 있는지 확인하세요. 잘 조율된 통합 설정은 인사이트의 신호를 높이고 잡음을 줄여줍니다.

## 통합 연결 끊기

통합 연결을 끊어야 할 경우:

1. **설정** > **통합 및 스마트 플로**로 이동합니다.
2. 제거하고 싶은 통합을 찾습니다.
3. 옆에 있는 **연결 해제**를 선택합니다.
4. 팝업 프롬프트에서 연결 해제를 확인합니다.

이를 통해 해당 출처에서의 미래 데이터 동기화가 중지됩니다.

> **중요**: Gong과 같은 경우에서는 연결을 해제하면 이전에 가져온 피드백 항목이 제거될 수도 있습니다. Jira와 같은 경우에서는 기존 기능이 유지되지만 업데이트는 받을 수 없습니다. 각 통합의 구체적인 동작을 문서에서 검토하거나 불확실한 경우 지원 센터에 문의하세요.

팀에 주요 소스를 연결 해제하는 경우 피드백과 백로그의 완성도에 영향을 미칠 수 있으므로 반드시 팀과 소통하세요.
