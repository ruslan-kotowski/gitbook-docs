이 문서에서는 우리 Jira 카드 통합이 어떻게 구축되었는지 대해 가장 자주 묻는 질문에 답합니다.

**보안**

**Jira-Miro 인증은 어떻게 작동하나요?**

도움말 센터 문서를 참조하세요

- **Jira 서버 온프레미스**
  - [OAuth 2.0](https://help.miro.com/hc/articles/25753304280466)
  - (서드파티) [OAuth 2.0](https://help.miro.com/hc/articles/25692796700306)
- **Jira Data Center 온프레미스**
  - [OAuth 2.0](https://help.miro.com/hc/articles/25753304280466)
  - (타사) [OAuth 2.0](https://help.miro.com/hc/articles/25692796700306)
- **Jira Cloud**
  Jira 카드 설정 페이지에서 선택하십시오.
  - [OAuth 2.0](https://help.miro.com/hc/articles/8588617184402) (3LO)

**Jira와 Miro 간의 데이터 전송은 안전하게 진행됩니까?**

우리는 TLS 보안 프로토콜을 사용합니다. 이는 전송 전에 HTTP 메시지를 암호화하고, 도착 시 메시지를 복호화합니다. Enterprise 플랜에서는 상호 TLS도 지원합니다. [자세히 알아보기](https://help.miro.com/hc/articles/360017730433).

**상호 TLS를 지원하나요?**

네, [자세히 알아보기](https://help.miro.com/hc/articles/4410562720658).

**Miro가 고객의 Jira 데이터를 보유하나요?**

네, Miro는 보드에 추가된 카드의 데이터를 보유합니다.

**보유 기간은 얼마나되며 데이터는 어떻게 보호됩니까?**

OAuth 1.0(Jira Server 또는 Data Center)에서도, Jira 카드 플러그인 설정 과정에서 웹훅이 구성된 경우 데이터가 업데이트됩니다. 보유 기간은 무제한이며, 일반 Miro 보안 프로토콜만 적용됩니다.

**Miro에서 가져오는 정보를 제한할 수 있나요?**

[Atlassian의 문서](https://developer.atlassian.com/server/jira/platform/webhooks/)에서는 몇 가지 필드로 정보를 제한하는 방법에 대한 언급을 찾지 못했습니다.

**Jira와 Miro 사이의 데이터 흐름을 보여주는 다이어그램을 받을 수 있나요?**

상세한 정보는 [이 Jira 개발자 기사](https://developer.atlassian.com/server/jira/platform/oauth/)에서 찾을 수 있습니다. 우리는 Atlassian 문서에 따라 통합을 구현합니다.

**토큰은 어떻게 처리되나요?**

Oauth 1.0: 엑세스 토큰만 사용됩니다. 엑세스 토큰은 [5년 동안 지속됩니다](https://developer.atlassian.com/server/jira/platform/oauth) (아틀라시안 측 정책에 의해 커스터마이즈할 수 없으며, Jira의 웹 UI를 통해 토큰을 취소할 수 있습니다). 각 새로운 토큰은 통합이 작동하지 않게 하며, [재연결](https://help.miro.com/hc/articles/360019501754#Step_2_-_Connection)이 필요합니다.

OAuth 2.0: 엑세스 토큰은 1시간 동안 유효합니다. 리프레시 토큰은 90일 동안 유효하며, 통합을 90일 동안 사용하지 않으면 다시 인증해야 합니다.

**모든 고객의 Jira 액세스에 단일 엑세스 토큰이 사용되나요?**

Jira 카드를 가져오거나, 생성하거나, 편집하려는 모든 Miro 사용자는 각자의 Jira 자격 증명을 연결해야 합니다. 위의 모든 작업은 각자의 Jira 자격 증명을 기반으로만 수행할 수 있습니다.

**요청 토큰, 액세스 토큰, 개인 키 및 기타 OAuth 비밀/신원 정보는 어떻게 보안이 유지되나요?**

통합 중에는 액세스 토큰만 사용되며, 이들은 데이터베이스 내에 안전하게 저장되고 서버 측에서만 사용됩니다.

OAuth 1.0(Jira 서버 및 데이터 센터)의 경우, authToken은 웹훅에만 사용됩니다. 이는 OAuth에서 사용되는 실제 인증 토큰이 아닙니다. 요청은 암호화된 연결을 통해 전송됩니다. 비밀 키는 자동 생성되며 팀별로 연관됩니다.


**카드는 Jira 데이터 센터와 함께 작동합니까?**

네. Atlassian의 승인에 따라, 이미 많은 고객들이 데이터 센터와 함께 Jira 카드를 성공적으로 사용하고 있습니다. 설치 절차는 동일합니다.

**Jira 시스템과 통신하기 위해 사용하는 IP는 무엇입니까?**

저희의 고정 IP 주소 목록은 [여기](https://help.miro.com/hc/articles/360017572694)에서 확인할 수 있습니다.

이 IP 주소들은 Jira 시스템과의 통신에만 사용된다는 점을 유의하세요. Miro 앱의 IP는 동적이므로, Miro 보드에서 Jira 카드와 관련된 일부 기능을 포함한 모든 기능이 성공적으로 수행될 수 있도록 저희 도메인을 [허용 목록에 추가할](https://help.miro.com/hc/articles/360017572694) 것을 요청드립니다.

**Jira를 Miro와 통합하되, 보안 수준이 "비공개"로 설정된 Jira 이슈는 차단할 수 있나요?**

아니요, 그 옵션은 없습니다. Jira의 보안 수준은 Miro와 연계되지 않습니다.

**일반**

**Jira 서버를 사용할 경우, Miro를 Jira에 연결할 수 있나요?**

Miro는 온라인 도구이기 때문에, 인스턴스가 공용 인터넷에 열려 있어야만 Jira에 연결할 수 있습니다.

**여러 Jira 인스턴스를 동시에 연결할 수 있나요?**

네. 그러나 Jira 인스턴스를 연결한다는 것은 초기 링크를 설정하는 것을 의미하며, 활성 연결은 현재 사용 중인 연결된 인스턴스를 지칭합니다. 활성 연결은 Jira 카드 앱을 열 때 Jira 카드가 가져오는 위치와 사용자가 인증된 인스턴스를 정의합니다. 특정 사용자에게는 한 번에 한 개의 활성 연결만 존재할 수 있습니다. OAuth 2.0에서는 사용자가 이미 인증된 모든 연결된 인스턴스에서 관련된 모든 Jira 카드를 편집할 수 있습니다. 다른 인증 프로토콜의 경우, 전체 팀이 하나의 활성 인스턴스를 공유하며, 해당 인스턴스에서만 카드를 가져오고 상호작용할 수 있습니다. 여러 조직 수준의 설정을 정의하고 팀 수준에서 활성 연결을 전환할 수 있습니다.

**서버에서 클라우드로 마이그레이션 프로세스는 무엇인가요?**

Jira 기본 URL이 Cloud로 마이그레이션되는 동안 반드시 변경될 것이므로, 당사에서는 변경 없이 통합이 중단됩니다. 지원이 필요하시면 [Miro](https://help.miro.com/hc/articles/360020185799)에 문의해 주세요.

**Miro가 팀당, 프로젝트당, 혹은 Miro 인스턴스당 하나의 웹훅을 생성합니까?**

Miro 설정에서 자동 웹훅을 활성화하면 웹훅 생성이 자동으로 이루어집니다. Jira와 팀 수준의 인증을 사용하는 경우, Miro는 팀별로 웹훅을 생성합니다. 조직 수준의 인증을 사용하는 경우에는 Miro가 조직별로 웹훅을 생성합니다.

**Jira 카드 플러그인이 차세대 프로젝트를 지원합니까?**

예, 지원합니다.

현재로서는 Miro에서 차세대 프로젝트를 위해 Jira 카드를 생성할 때 에픽 링크/필드가 없음을 참고 바랍니다.

**맞춤형 Jira 필드가 지원됩니까?**

네, 우리는 대부분의 *기본* 유형의 사용자 지정 필드를 지원합니다. *복합* 데이터 유형 필드의 경우 지원되지 않을 수 있으며, 보드에서 Jira 카드를 업데이트하거나 생성할 때 예기치 않은 동작이 발생할 수 있습니다.

**다른 Jira 인스턴스로 전환할 경우 기존 Jira 카드는 어떻게 되나요?**

현재, Jira에서 한 프로젝트에서 다른 프로젝트로 Jira 이슈를 이동하면 Miro 측에서는 더 이상 업데이트되지 않습니다.

해결책으로, Jira 이슈 URL을 복사(Ctrl/Cmd+C)하여 Miro 보드에 붙여넣기(Ctrl/Cmd+V) 하면, 새로운 값이 표시되고 자동으로 업데이트되는 Jira 카드가 생성됩니다.

**보드가 다른 Miro 팀으로 이동되면 보드의 Jira 카드는 어떻게 되나요?**

Jira 카드는 보드에 남아 있지만, 아무도 이를 수정할 수 없게 됩니다 (대상 팀에 동일한 Jira 인스턴스가 구성된 경우라도).

카드를 클릭하면, *"JIRA 카드를 다른 계정에서 가져왔습니다"*라는 메시지를 볼 수 있습니다. 카드를 편집 가능하게 하려면 새로 보드로 가져오세요.

**Jira 카드 통합에 추가 비용이 있나요?**

Jira 카드는 모든 유료 및 Education 플랜에서 추가 비용 없이 사용할 수 있습니다 (Starter, Business, Education, Enterprise 플랜).

**사용자가 보드의 모든 Jira 카드를 접근할 수 있나요?**

Jira 카드 통합의 권한은 사용자가 접근 권한을 가진 Jira 프로젝트 내에서만 카드 생성 및 편집을 할 수 있도록 보장합니다.

모든 Miro 보드 위젯은 보드에 접근 권한이 있는 모든 사용자에게 보이므로, Jira 자격 증명이 없거나 올바른 자격 증명이 없는 경우에는 Miro 보드에서 축소된 Jira 카드(제목 및 다른 일부 필드 포함)를 볼 수 있지만, 카드를 확장하여 완전하게 검토하거나 수정할 수는 없습니다.

**Atlassian에서 Jira 서버에 대한 지원을 중단했나요?**

네, Atlassian은 2024년 2월부로 Jira 서버에 대한 지원을 중단했습니다.

**Miro 플래너/Jira 카드가 Jira의 사용자 지정 필드인 사용자 지정 이슈 유형과 사용자 지정 종속성을 지원하나요?**

네, 둘 다 지원합니다. **사용자 지정 이슈 유형**과 **사용자 지정 종속성** 필드가 Jira에 설정되어 있고, *Miro 플래너*가 해당 Jira 인스턴스에 인증되어 있는 경우, 이 사용자 지정 필드는 플래너에서 사용할 수 있습니다.

**Miro가 Jira 데이터 센터에 대해 OAuth 2.0을 지원하나요?**

네. [OAuth 2.0을 사용하여 Jira 데이터 센터에 연결하기](https://help.miro.com/hc/articles/25753304280466)를 참조하세요.

**테이블 및 타임라인의 Jira 카드**

**어떻게 Jira 이슈를 테이블과 타임라인으로 가져올 수 있나요?**

여러 Jira 카드를 테이블이나 타임라인에 직접 드래그 앤 드롭할 수 있습니다. 현재로선 이것이 유일한 방법입니다.

**테이블의 모든 필드가 Jira와 연동되나요?**

아니요, 초기 릴리즈에서는 테이블의 다섯 개 필드만 Jira와 동기화됩니다:

세 가지 시스템 Jira 필드:

- 제목
- 설명
- 종료일 (Jira에서는 마감일로 표시됨)

두 가지 맞춤형 Jira 필드:

- 시작일
- 추정치

**어떤 테이블 필드가 Jira와 동기화되지 않습니까?**

담당자와 상태 필드는 Jira와 동기화되지 않으며 테이블과 타임라인에서 비활성화됩니다. 이 필드와 그 내용은 존재하지만 테이블과 타임라인에서는 보이거나 편집할 수 없습니다.

이 필드는 여전히 Jira 카드 측면 패널에서 직접 편집할 수 있습니다. 테이블이나 타임라인에서 행을 캔버스로 끌어다 놓으면 Jira 카드가 다시 나타납니다.

위에서 언급한 다섯 개의 필드(제목, 설명, 종료일, 시작일, 추정치)를 제외한 다른 모든 필드는 Miro에만 저장되며 Jira와 동기화되지 않습니다.

**위에서 언급한 지원되는 다섯 가지 Jira 필드 중 하나를 테이블이나 타임라인에서 편집할 수 없는 이유는 무엇입니까?**

해당 필드가 Jira의 편집 화면에 없을 수 있습니다.

필드가 편집 화면에 있는지 확인하는 간단한 방법:

Miro에서 Jira 카드의 측면 패널을 엽니다. 필드가 측면 패널에 있는지 확인하세요. 필드가 없으면 Jira의 편집 화면에 해당 필드를 추가해야 합니다.

드물게 Jira에서 필드를 편집할 수 있지만, Jira의 편집 화면에는 없는 경우가 있습니다. 이 경우에는 Miro에서 필드를 편집할 수 없습니다.

편집할 수 없는 필드가 **시작일** 또는 **예상치**입니까? 그렇다면:

필드가 Jira에 없거나 편집 화면에서 누락되었을 수 있습니다 (이전 포인트 참조).

시작일이나 예상치는 맞춤형 Jira 필드이므로 매핑 문제가 있을 수 있습니다.

이러한 필드를 다음 논리에 따라 매핑합니다:

- **시작 날짜**: 확인하는 필드 이름: Start Date, StartDate, Target Start
- **예상치**: 확인하는 필드 이름: 스토리 포인트, Story point estimate, 스토리 포인트, StoryPoints, StoryPoint
- 시작 날짜 또는 예상 필드의 이름이 위의 목록에 포함되어 있지 않다면, 편집이 제대로 작동하지 않는 이유를 설명할 수 있습니다.

**왜 Miro의 테이블이나 타임라인에서 시작 날짜 또는 견적을 편집할 때 작동하지 않거나 Jira의 잘못된 필드를 업데이트하나요?**

현재 Miro는 Jira의 시작 날짜 및 견적 필드에 대해 자동화된 매핑을 사용하고 있습니다. 이 필드들은 Jira에서 사용자 지정 필드이기 때문에 위의 기준에 맞는 여러 필드가 귀하의 Jira 설정에서 일치할 수 있습니다.

우리는 위에 언급된 필드명 순서에 따라 첫 번째로 일치하는 항목을 선택합니다:

예를 들어, Jira 티켓에 "스토리 포인트"와 "스토리 포인트 추정" 필드가 모두 있는 경우, 우리는 위의 목록에 따라 첫 번째 항목인 "스토리 포인트"에 일치시킵니다. 따라서 테이블 내 "견적" 필드에 대한 변경 사항은 Jira의 "스토리 포인트" 필드를 업데이트하며, "스토리 포인트 추정"은 업데이트되지 않습니다.

현재로서는 이에 대한 해결 방법이 없습니다. 이러한 문제가 발생하면, 더 고급 필드 매핑 기능을 개발할 수 있도록 귀하의 지원 팀에 피드백을 보내주시기 바랍니다.

**왜 두 개의 다른 인스턴스에서 Jira 카드를 테이블이나 타임라인에 가져올 수 없나요?**

현재 각 테이블/타임라인당 하나의 Jira 인스턴스만 지원합니다. 테이블/타임라인에 Jira 카드를 가져오면 해당 테이블/타임라인은 그 특정 Jira 인스턴스와 연결됩니다.

모든 Jira 기록을 삭제하더라도, 원래의 Jira 인스턴스와의 연결은 남아 있게 됩니다. 다른 Jira 인스턴스에서 카드를 가져오려면 새로 테이블/타임라인을 만들어야 합니다.

**왜 테이블이나 타임라인에서 Jira 기록의 상태와 담당자 필드를 볼 수 없거나 편집할 수 없나요?**

현재 테이블과 타임라인에서는 Jira의 상태 및 담당자 필드가 지원되지 않습니다. 기대치를 관리하고 혼란 및 잠재적인 데이터 손실을 방지하기 위해 테이블과 타임라인에서 이러한 필드를 사용 중지하기로 결정했습니다. Jira의 상태와 담당자 필드 및 그 내용은 존재하지만, 테이블이나 타임라인에서는 나타나지 않습니다.

이러한 필드는 여전히 Jira 카드에서 측면 패널을 사용하여 직접 편집할 수 있습니다. 테이블이나 타임라인에서 행을 캔버스로 끌어다 놓으면 Jira 카드가 다시 나타납니다.
