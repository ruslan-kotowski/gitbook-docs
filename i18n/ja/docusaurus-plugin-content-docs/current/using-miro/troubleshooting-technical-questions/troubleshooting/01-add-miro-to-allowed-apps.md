Miro にアクセスが許可されていないと、Miro の機能が正常に動作しない場合があります。これは、ネットワーク接続または使用環境の問題や制限によって発生する可能性があります。以下の記事では、そのような問題の最も一般的な原因を記載しています。

## WebSocket

Miro のアプリケーション、具体的には*ボード*のページでは、WebSocket 接続が必要です。ダッシュボードや設定ページは期待通り開くのに、ボードを開く際に問題が発生する場合は、WebSocket 接続がサポートされていない可能性があります。

接続をテストするには、[このウェブサイト](http://websocketstest.com)を開いてください。

WebSocket が識別されると、以下のメッセージが表示されます。

![wensocket_connection.jpg](../../../../../../../docs/using-miro/troubleshooting-technical-questions/troubleshooting/images/21020264610066_wensocket%20connection.jpg)

異なる結果になった場合は、お使いのネットワークに WebSocket 接続をブロックするものがある可能性が高いです。その場合は、以下をお試しください。

- 別のネットワーク接続を使用する
- VPN を使用する、またはオフにする
- 会社の接続を使用する場合は、ネットワーク管理者に連絡し、ポート 80 および 443（SSL）の WebSocket 接続を有効にするよう依頼してください。セキュリティーの観点から、このポートは、会社のネットワーク内で閉じられているか、フィルターがかけられている可能性があります。接続を確立するには、Miro のアドレスがアクセスできるように、これらのポートを開く必要があります（アドレスについては、以下の「ファイアウォールを使用する場合」のセクションを参照してください）

WebSocket が正しく識別されても、接続の確立に引き続き問題が発生する場合は、[Miro サポート](https://help.miro.com/hc/requests/new?referer=help-center-article)にご連絡ください。

### Miro ドメインの許可リスト

保護されたネットワークを使用する組織は、すべての Miro ドメインを許可する必要があります。許可する必要のあるドメインの完全なリストについては、[Miro ドメイン](../technical-guidelines/07-miro-domains-reference.md)を参照してください。

## プロキシーを使用する場合

Miro に必ずバイパスを提供してください。以下の仕様が役に立ちます。

- プロキシーサーバーは、WebSocket 接続（HTTP/2）をサポートする必要があります。
- プロキシー HTTP バージョンは 1.1 に設定する必要があります。
- 送信元 IP/ ホスト：上記の NAT IP を確認してください（Atlassian のインテグレーションのみに使用）。
- 送信元ポート: **80。** 80 は、HTTP 経由で Miro にアクセスするユーザーを HTTPS に転送するのに使用されます（80 をブロックすることはお勧めしません）。
- 宛先ポート: **443（SSL）。**443 は HTTPS に使用されます。
- プロトコル：HTTPS
- TLS：1.2。（Miro は AWS でホストされており、AWS セキュリティー ポリシーを使用しています。AWS と Miro のすべてのプラグインパートナーが 1.3 に対応するようになれば、Miro も移行が可能になります）。
- プロキシーサーバーのタイムアウト値を延長する必要があります。お使いのシステムでは接続まで約 60 ～ 90 秒待機する場合が多いと思われますが、120 ～ 180 秒に延長するのが最善です。
- プロキシーサーバーは、要求ヘッダーと応答ヘッダーを切り捨てるべきではありません。*Upgrade* ヘッダーと *Connection* ヘッダーが、クライアントによりプロキシーされているか確認してください。
