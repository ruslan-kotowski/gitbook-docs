## コンテンツ セキュリティー ガードレール

以下の表に、現在のリリースでサポートされているコンテンツ セキュリティー ガードレールを示します。

|  |  |  |
| --- | --- | --- |
| **ガードレール** | **説明** | **影響を受けるユーザー** |
| **コンテンツの複製をブロック** | - Miro UI と Miro API の両方でコンテンツの複製を管理するオプションは利用できません。例えば、ボードコンテンツをコピーできるユーザーを更新するオプションはUIで利用できず、ボードAPIを使用してコピーアクセスを更新するオプションも利用できません。  - コンテンツの複製に関するオプションは、Miro UIでは利用できません。これには次が含まれます。     - ボードを他の     ユーザーのチーム     - ボード上のファイルをダウンロードする     - ボード上の画像をダウンロードする     - ボード上でPDFをダウンロードする     - コンテンツやオブジェクトをコピーするために      ボードを別のボードに     - ボードを画像としてエクスポートする     - PDF としてボードをエクスポートする     - ボードをカスタムとして保存する      テンプレート     - API 経由でのコンテンツの複製は      ご利用いただけません。API は次のエラーを返します      応答としてエラー 403 が返されます。 | ボードの所有者と共同所有者は制限されていません。ボードの所有者と共同所有者は、コンテンツの複製アクションを実行できます。これは、ボードの所有者がボードを更新し、将来的なコラボレーションのためにサニタイズされたバージョンを作成するために必要です。  それ以外の方は制限されています。 |
| **Miro AI の使用をブロック** | - すべての Miro AI 機能が無効化されており、テキスト生成、画像認識、スマート提案などのAIを利用した機能へのアクセスができません。  - ユーザーは Miro 内の AI 搭載ツールとやり取りしたり、これらのツールを起動したりすることができません。  - 既存の Miro AI 生成コンテンツは変更されず、ユーザーはこのコンテンツを修正または拡張することができます。しかし、ユーザーはもう Miro AI を使ってコンテンツを編集したり更新したりすることができません。 | ボードの所有者と共同所有者を含む全員が制限されています。 |

## 共有ガードレール

以下の表は、現在のリリースでサポートされている共有ガードレールを一覧表示しています。

|  |  |  |
| --- | --- | --- |
| **ガードレール** | **説明** | **影響を受けるユーザー** |
| **公開共有をブロック** | - Miro の UI で「*リンクを知る全員*」と共有するオプションは利用できません。  - API 経由での公開共有は利用できません。API はエラー 403 を応答として返します。  - ライブ埋め込みのアクセスリンクを使用して埋め込まれたボードには、公開共有のブロックは適用されません。これらのボードは公開リンクを介して共有されているとみなされないためです。詳細については、[対応アプリへの Miro ボードの埋め込みを許可または制限する方法](../../managing-apps-on-enterprise-plan/05-how-to-allow-or-restrict-embedding-miro-boards-in-supported-apps.md)をご覧ください。 | ボード所有者を含む全員が制限されています。 |
| **チームとの共有をブロック** | Miro の UI では、*「チームの全員」*と共有するオプションは利用できません。  - API を通じてチームで共有することはできません。API はエラー 403 を返します。 | ボード所有者を含む全員が制限されています。 |
| **組織との共有をブロック** | - 「組織の全員」と共有するオプションは*Miro UI*では利用できません。  - API を通じて組織で共有することはできません。API はエラー 403 を返します。 | ボード所有者を含む全員が制限されています。 |
| **許可ドメイン以外は共有をブロックする** | - ボードは、ここに記載された許可ドメインに属するメールアドレスを持つユーザーのみ、直接メール招待で共有できます。このガードレールは、チーム、組織、または公開リンクを通じて付与されたアクセスには影響しません。これらは別のガードレールによって管理されています。  このリストには最大 20 件まで許可ドメインを追加できます。  このガードレールは、組織レベルおよびチームレベルの両方で設定できる[**セキュリティ > 共有 > 許可ドメイン**](../data-security/07-sharing-policy-on-enterprise-plan.md)設定と連携するように設計されています。つまり、**許可ドメイン**設定が有効になっている場合、許可したいボードを共有するドメインが、[**セキュリティ > 共有 > 許可ドメイン**](../data-security/07-sharing-policy-on-enterprise-plan.md)設定とインテリジェントガードレール設定の両方に記載されていることを確認する必要があります。   **注:**  このリストにないメールアドレスで既にボードが共有されている場合、すでにボードへのアクセス権を持つユーザーは、引き続きアクセスできます。  既存のユーザーで、ボードにアクセスできるが許可されたドメインリストにない場合は、ボードアクセス管理UIに表示されます。これらのユーザーのアクセス権を手動で削除できます。 機密分類ページを通じて適用されるドメイン制限の情報を簡単に閲覧できます。   **例 1:** **セキュリティ > 共有 > 許可ドメイン:** miro.com, gmail.com  **ガードレール許可ドメイン:** miro.com  ***結果:*** ボードの共有は、miro.com で終わるメールアドレスへの直接メール招待に限定されています。セキュリティ > 共有 > 許可ドメイン設定では gmail.com が許可されていますが、ガードレールでは許可されていません。  **例 2:** **セキュリティ ＞ 共有 ＞ 許可されたドメイン:** miro.com, gmail.com  **ガードレール許可ドメイン:** example.org, example.com  ***結果:*** メールによる直接招待でのボード共有は、リストが重複しないため、どのドメインにも許可されていません。 | メールによる直接招待でのボード共有は、このリスト上の許可されたドメインに属するメールアドレスを持つユーザーに限定されています。このガードレールは、チーム、組織、または公開リンクを通じて許可されたアクセスには影響しません。これらは別のガードレールによって管理されています。  ボードがこのリストに含まれていないメールアドレスと既に共有されている場合、既にボードにアクセス権を持っている人々は継続してアクセスできます。   このガードレールは、[**セキュリティ ＞ 共有 ＞ 許可されたドメイン**](../data-security/07-sharing-policy-on-enterprise-plan.md) 設定と連携するように設計されており、組織およびチームレベルで構成できます。詳細な説明と例については、説明欄をご参照ください。 |
