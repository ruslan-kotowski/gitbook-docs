すべてのライセンスリクエストを1か所で管理します。Miroで直接ライセンスリクエストを受け取ることにより、組織内でのライセンス使用と承認プロセスを簡素化できます。

## ライセンスリクエストの設定

**アクセスリクエスト**の設定内で、現在のすべての**ライセンスリクエスト**の概要を確認できます。これらのライセンスリクエストは、ユーザーがFree RestrictedからAdvanced、Standard、またはFull（レガシー）のライセンスにアップグレードを必要とする場合に開始されます。

ライセンスリクエストの詳細には以下が含まれます。

- ライセンスが必要なユーザー名
- ユーザーが割り当てられる支払いグループ名（ある場合）
- 依頼者名
- 依頼日

リクエストは、ライセンスのアップグレードを必要とする本人または他人に代わって提出することができます。Enterprise プランのさまざまなライセンスアップグレードのシナリオについて学びましょう。

:::note
ライセンスリクエストをMiroで直接受け取るには、[リクエスト管理](09-request-management-on-enterprise-plan.md)の設定を更新してください。
:::

## ライセンスリクエストを承認または拒否する方法

:::note
すべてのリクエストは 30 日後に自動的に期限切れとなり、削除されます。
:::

1. Miro の設定に移動します。
2. [**会社**] をクリックします。
3. [**ユーザー**] の下で、[**アクセス リクエスト**] をクリックします。
4. [**ライセンスリクエスト**] タブを選択します。ここでは、すべての保留中のライセンスリクエストを表示できます。
5. [**操作**] 列の下で、チェックマーク (**✓**) をクリックしてリクエストを承認するか、または×(**x)**をクリックして拒否します。
6. （オプション）ライセンスリクエストを一括承認するには、**名前**列の隣にあるチェックボックスをクリックしてすべてのリクエストを選択し、**一括承認**をクリックします。
7. リクエストを承認または却下すると、リクエスターの詳細とライセンスリクエストの対象者情報が含まれたモーダルが開きます。
8. リクエストを認可するには**承認**を、リクエストを却下するには**却下**をクリックします。リクエストを承認または却下すると、ライセンスリクエストの概要からそのリクエストが削除されます。
9. ライセンスリクエストが承認されると、ユーザーはFree RestrictedからAdvanced、Standard、またはFull（レガシー）のライセンスにアップグレードされます。

## ライセンスアップグレードのシナリオ

特定のアクションやイベントが Miro で発生すると、ユーザーはライセンスのアップグレードリクエストを提出するよう促されます。以下に示すシナリオは、Enterprise プランのユーザーがどのようにこれらのリクエストを開始するかを説明しています。承認されると、ユーザーのライセンスは Free Restricted から Advanced、Standard、または Full (従来) ライセンスにアップグレードされます。ユーザーは、以前所属していたチームのメンバーシップを保持します。

:::note
現在のライセンス使用状況を確認するには、**ユーザー管理** > **アクティブユーザー** に移動します。
:::

|  |  |  |
| --- | --- | --- |
| **ユーザータイプ** | **アクション** | **シナリオ** |
| **既存メンバー（制限付き無料ライセンス）** | ボードやプロジェクトを作成 | 制限付き無料ユーザーがチーム内で新しいボードやプロジェクトの作成を試みる |
| 編集アクセス | 制限付き無料ユーザーがボードの編集権限をリクエスト |
| 編集に招待 | 既存のメンバーが、Free Restricted ユーザーに編集アクセスをリクエストする |
| ボードの所有者 | Free Restricted ユーザーがチームの管理者によって[ボード所有者](../../getting-started/start-here/05-roles-in-miro.md)の役割に割り当てられる |
