Miro では、ライセンス、チームおよび組織へのアクセス、シングルサインオン（SSO）の各種リクエストは、デフォルトで会社の管理者にメールで送信されます。高度なリクエスト管理機能により、会社の管理者はこれらのリクエストの受信と処理方法をカスタマイズできます。

### リクエストの種類

リクエストの種類は 4 つに分類されます：

- 組織への参加リクエスト
- チームへの参加リクエスト
- ライセンスのリクエスト
- SSO の問題に関するリクエスト

Enterprise プランのさまざまなリクエストシナリオについてご紹介します。

### リクエスト管理オプション

会社の管理者には様々なリクエスト管理のオプションがあり、リクエストの種類に応じてプロセスをカスタマイズすることができます：

:::note
会社の管理者全員、または特定の会社の管理者にメールを送信するオプションには、チームの管理者も含まれます。
:::

- すべての会社の管理者にメールを送信する
- 特定の会社の管理者にメールを送信する
- サービスデスク チケットを作成する
- カスタム URL にリダイレクトする

## リクエスト管理の設定

:::note
[Miroで直接ライセンスリクエストを管理する](04-license-requests-on-enterprise-plan.md)には、**すべての会社の管理者にメールを送信する**または**特定の管理者にメールを送信する**を選択してください。今後のライセンスリクエストはすべて、ライセンスリクエスト設定で受け取ることになります。
:::

### すべての会社の管理者にメールを送信する

ユーザーがアクセスリクエストをすると、すべての会社の管理者にメール通知が届きます。

1. 会社設定で**ユーザー**に移動し、**アクセスリクエスト** > **リクエスト管理** をクリックします。
2. 管理したい**リクエストの種類**をクリックします。
3. ポップアップが開きます。ドロップダウンをクリックして**すべての会社の管理者にメール送信**を選択します。

:::note
すべての会社の管理者、または特定の会社の管理者にメールを送信するオプションにはチームの管理者も含まれます。
:::

### 特定の会社の管理者にメールを送信

会社の管理者は、メールアドレスを最大 5 件まで指定できます。指定したメールアドレスにのみリクエストが届きます。メールアドレスは、Miro のユーザーである必要はありません。

1. **会社**設定 > **ユーザー** > **アクセスリクエスト** > **リクエスト管理**に進みます。
2. 管理したい**リクエストの種類**をクリックします。
3. ポップアップが開きます。ドロップダウンをクリックして、**特定の会社の管理者にメールを送信**を選択します。
4. 最大5件までメールアドレスを追加します。メールアドレスを入力するごとに**追加**をクリックします。

:::note
すべての会社の管理者、または特定の会社の管理者にメールを送信するオプションには、チームの管理者も含まれます。
:::

### サービスデスク チケットを作成

ユーザーがアクセスをリクエストするたびに、サービスデスク チケットが自動作成されます。この機能は現在**ServiceNow**と**Jira Service Management**に対応しています。

ServiceNow Jira Service Management

1. ServiceNow のメール設定を行います。ServiceNow で Miro のカタログアイテムを作成します。ServiceNow を開き、**System Properties** > **Email Properties** に移動し、メールの受信を有効にします。

2. [受信メールアクションを作成](https://docs.servicenow.com/bundle/tokyo-servicenow-platform/page/administer/notification/task/t_CreatingAnInboundEmailAction.html)します。「**この送信者からのメールのみがこの受信アクションをトリガーします**」という行の「From」フィールドに notification@miro.com と入力します。**Only emails from this sender will trigger this inbound action**（この送信者のメールのみがこの受信アクションをトリガーする）行の下にある差出人フィールドに、[notification@miro.com](mailto:notification@miro.com) を入力します。

3. [メール本文からフィールド値を設定する](https://docs.servicenow.com/bundle/rome-servicenow-platform/page/administer/notification/reference/r_SetFieldValsFromTheEmailBody.html) ことによって、追加の設定を構成し、Miro のメールを ServiceNow チケットに変換するプロセスを設定します。例えば、新しく作成したチケットを特定のユーザーに割り当てることができます。

4. Miro に移動し、**Company** 設定 > **Users** > **アクセスリクエスト** > **リクエスト管理**を選択し、**ServiceNow でチケットを作成**を選択します。メールアドレスのフィールドに、ServiceNow のメールアドレスを入力します。

1. Jira Service Management で、メール設定を行います。サービスプロジェクトから、**プロジェクト設定** > **メールリクエスト** を選択します。[使用するメールサービスプロバイダーを選択し、Miro とリンクする手順に従ってください](https://support.atlassian.com/jira-service-management-cloud/docs/receive-requests-from-an-email-address/)。

2. Miro に行き、**会社**設定を開き、**ユーザー管理**> **アクセスリクエスト** > **リクエスト管理**で、**Jira Service Management にチケットを作成**を選択します。メールアドレス欄に、Jira Service Management のメールアドレスを入力します。

### カスタム URL にリダイレクト

リクエストしたユーザーは、次のステップで、選択した URL にリダイレクトされます。

1. 会社設定の**ユーザー**に移動し、**アクセスリクエスト** > **リクエスト管理**。
2. 管理したい**リクエストの種類**をクリックします。

- ポップアップが開きます。ドロップダウンをクリックし、**カスタム URL にリダイレクト**を選択します。
- リダイレクトリンクを**カスタム URL**フィールドに入力します。

## リクエストのシナリオ

以下のシナリオでは、Miro で各種リクエストがどのように開始されるかを概説します。シナリオを確認して、それぞれのリクエスト種別をどのように管理するかを決定してください。

|  |  |
| --- | --- |
| **組織への参加リクエスト** | - 新しいユーザーが[ドメイン制御](../canvas-25-admin-features/domain-control/01-domain-control.md)が設定されている会社管理サブスクリプションのチームに参加をリクエストしたとき（新しいユーザーをキャプチャするようにドメイン制御が設定されていない限り）。 |
| **ライセンスリクエスト** | - [Free Restricted ユーザー](../enterprise-subscription-management/enterprise-licensing/04-free-restricted-license.md)が Standard または Full (旧版) ライセンスをリクエストする場合。 - メンバーがスタンダードまたはフル（レガシー）ライセンスを制限付き無料ライセンスのユーザーに対してリクエストする場合、メンバーが新しいユーザーをサブスクリプションに招待することが許可されていない限り、[招待の設定](03-invitation-settings-on-enterprise-plan.md)。 - スタンダードまたはフル（レガシー）ライセンスを持つユーザーがアドバンスドライセンスをリクエストする場合。 - メンバーが、制限付き無料ライセンスを持つユーザーを招待する、または編集権限を与えようとする場合。 |
| **チームへの参加リクエスト** | - 管理者ではないユーザーが、*チームメンバーでない*ユーザーとボードを共有しようとしたとき、[招待設定](03-invitation-settings-on-enterprise-plan.md)でゲスト招待がオフになっており、管理者のみがチームに新しいメンバーを招待できます。 - 新しいメンバーを招待する権限がないメンバーが、特定のボードでチームのメンバーではないユーザーに所有者または[共同所有者](../../using-miro/sharing-boards/06-co-owners-of-boards-and-spaces.md)の役割を与えようとした場合。 - Enterpriseユーザーが所属する組織内で[ユーザーが発見できるように設定されたチーム](../managing-enterprise-teams-and-content/11-manage-team-privacy-and-discovery-on-enterprise-plan.md)への参加をリクエストする場合。 - チーム内の特定のボードに招待された[ゲスト](../../using-miro/sharing-boards/07-collaboration-with-guests.md)が、チームへの参加をリクエストする場合 |
| **SSO の問題に関するリクエスト** | - IdP で Miro へのアクセスがユーザーに与えられておらず、SSO 経由でのログインに問題がある場合。 |

## よくある質問

**チケットを作成するよう設定したにも関わらず、メールが送信されてくるのはなぜですか？**

もし [招待設定](03-invitation-settings-on-enterprise-plan.md)でチームの管理者がチームに新規ユーザーを招待することを許可されている場合、リクエスト管理の設定が異なっていても、メールでこのチームに関連する招待リクエストを受信します。 チームの管理者でもある会社の管理者もこれらのメールを受け取ることになります。

**チームの管理者は、チームへの参加リクエストがあった場合、どのように知らせてもらえるのですか？**

チームにユーザーを招待できる許可を与えられているチームの管理者には、リクエスト管理の設定に関係なく、リクエストに関するメールが届きます。
