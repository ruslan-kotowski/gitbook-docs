この記事では、Jira カードのインテグレーションがどのように構築されているかに関する最もよくある質問に回答します。

**セキュリティ**

**Jira-Miro の認証はどのように行われますか？**

詳細はヘルプセンターの記事をご覧ください。

- **Jira サーバー（オンプレミス）**
  - [OAuth 2.0](https://help.miro.com/hc/articles/25753304280466)
  - （サードパーティ）[OAuth 2.0](https://help.miro.com/hc/articles/25692796700306)
- **Jira データセンター（オンプレミス）**
  - [OAuth 2.0](https://help.miro.com/hc/articles/25753304280466)
  - （サードパーティ）[OAuth 2.0](https://help.miro.com/hc/articles/25692796700306)
- **Jira クラウド**
  Jira カード設定ページから選択します。
  - [OAuth 2.0](https://help.miro.com/hc/articles/8588617184402)（3LO）

**Jira と Miro 間で転送されるデータは保護されていますか？**

Miro では、TLS セキュリティ プロトコルを使用しています。送信前に HTTP メッセージを暗号化し、受信時にメッセージを解読します。また、[Enterprise プラン](https://help.miro.com/hc/articles/360017730433)では、相互 TLS もサポートしています。

**相互 TLS をサポートしていますか？**

はい、[詳細はこちら](https://help.miro.com/hc/articles/4410562720658)。

**Miro は、顧客の Jira データを保持しますか？**

はい、Miro は、ボードに追加されたカードのデータを保持します。

**保管期間はどのくらいで、データの保護はどのように行われますか？**

OAuth 1.0 の場合（Jira サーバーまたはデータセンター）、また、Jira カードのプラグインの設定プロセス中に Webhook が設定されている場合、データは更新されます。保管期間に制限はありません。一般的な Miro のセキュリティ プロトコルのみが適用されます。

**Miro から取得できる情報を制限することは可能ですか？**

[Atlassian のドキュメンテーション](https://developer.atlassian.com/server/jira/platform/webhooks/)には、情報をいくつかのフィールドに制限する方法についての記載はありませんでした。

**Jira と Miro 間のデータフローを示す図を用意できますか？**

詳細情報は[このJira開発者の記事](https://developer.atlassian.com/server/jira/platform/oauth/)で確認できます。私たちは Atlassian のドキュメンテーションに従ってインテグレーションを実施しています。

**トークンの取り扱いはどのように行っていますか？**

Oauth 1.0：アクセス トークンのみが使用されます。アクセス トークンは [有効期間は 5 年ですが、](https://developer.atlassian.com/server/jira/platform/oauth)取り消されない限り続きます（カスタマイズするオプションはありません。このポリシーは Atlassian 側で定義されています。Web UI を使用して Jira 側でトークンを取り消すことができます）。新しいトークンが発行されるたびにインテグレーションが動作しなくなり[再接続](https://help.miro.com/hc/articles/360019501754#Step_2_-_Connection)が必要です。

OAuth 2.0：アクセストークンは 1 時間有効です。リフレッシュトークンは 90 日間有効です（90 日間インテグレーションを使用しない場合は再認証が必要です）。

**顧客全員の Jira アクセスに 1 つのアクセストークンを使用していますか？**

Jira カードをインポート、作成、編集しようとするすべての Miro ユーザーは、個々の Jira 資格情報を接続する必要があります。上記のすべての操作は、個々の Jira 資格情報に代わってのみ行うことができます。

**リクエストトークン、アクセストークン、秘密鍵、その他の OAuth 秘密/認証情報はどのように保護されていますか？**

インテグレーション時には、アクセストークンのみが使用されます。これらは、データベース内で安全に保管され、サーバー側でのみ使用されます。

OAuth 1.0 の場合（Jira サーバーとデータセンター）、authToken は Webhook にのみ使用されます。これは、OAuth によって使用される実際の認証トークンではありません。リクエストは、暗号化された接続を介して送信されます。秘密鍵は自動生成され、チームごとに関連付けられます。

**カードは Jira のデータセンターと連携していますか？**

はい。Miro は Atlassian の承認を受けており、既に多くのお客様がデータセンターで Jira カードを使用しています。インストール手順は同じです。

**どの IP を使用して Jira システムと通信していますか？**

私たちの静的 IP アドレス一覧は[こちら](https://help.miro.com/hc/articles/360017572694)で確認できます。

これらは Jira システムと通信するためにのみ使用されるアドレスですのでご注意ください。Miro アプリの IP は動的であり、Miro のボード上のすべての機能（Jira カードに関連するものを含む）が正常に動作するように、[Miro のドメインを許可リストに追加](https://help.miro.com/hc/articles/360017572694)してください。

**Jira を Miro と統合し、セキュリティレベルが「非公開」に設定されている Jira 課題を Miro でブロックすることは可能ですか？**

いいえ、それはできません。Jira のセキュリティレベルは、Miro と相関関係がありません。

**一般**

**Jira サーバーを使用している場合でも、Miro と Jira を接続できますか？**

Miro はオンラインツールのため、インスタンスが公共のインターネットに公開されている場合にのみ Jira と接続することができます。

**複数の Jira インスタンスを同時に接続できますか？**

はい。ただし、Jira のインスタンスを接続するということは、初期リンクを確立することであり、アクティブな接続とは、現在使用中のリンクされたインスタンスを指します。アクティブな接続は、Jira Cards アプリを開いたとき、どのインスタンスから Jira Cards がインポートされるか、およびどのインスタンスにユーザーが認証されているかを定義します。特定のユーザーには、一度に 1 つのアクティブな接続しか存在できません。OAuth 2.0 を使用すると、ユーザーはすでに認証されているリンクされたすべてのインスタンスに関連する Jira Card を編集できます。他の認証プロトコルの場合、ユーザー全体がチーム内でアクティブなインスタンスを共有し、そのインスタンスからのみカードをインポートおよび操作できます。複数の組織レベルの設定を定義し、チームレベルでアクティブな接続を切り替えることができます。

**サーバーからクラウドへの移行プロセスはどうなりますか？**

クラウドへの移行中に Jira ベースの URL が変更されることは避けられないため、Miro 側で変更しなければインテグレーションは中断されます。サポートが必要な場合は、[Miro サポート](https://help.miro.com/hc/articles/360020185799)にお問い合わせください。

**Miro は、チームごと、プロジェクトごと、または Miro のインスタンスごとに Webhook を作成しますか？**

自動 Webhook を Miro の設定で有効にした場合、Webhook は自動的に作成されます。Jira のチームレベルの承認を使用する場合、Miro はチームごとに Webhook を作成します。組織レベルの承認を使用する場合は、Miro は組織ごとに Webhook を作成します。

**Jira カードプラグインは、Next-Gen プロジェクトをサポートしていますか？**

はい、しています。

現在、Miro 側で Next-Gen プロジェクト用の Jira カードを作成する場合、エピックのリンク/フィールドがないことにご注意ください。

**カスタム Jira フィールドはサポートされていますか？**

はい、*基本的な*タイプのカスタムフィールドはほとんどすべてサポートしています。*複雑な*データタイプのフィールドがある場合、ボード上でJiraカードを更新または作成する際にはサポートされず、予期しない動作を引き起こす可能性があります。

**別のJiraインスタンスに切り替えた場合、既存のJiraカードはどうなりますか？**

現時点では、Jira課題を1つのプロジェクトから別のプロジェクトに移動した場合、Miro側では更新されなくなります。

対応策として、Jira課題のURLをコピーし（Ctrl/Cmd+C）、Miroのボードに貼り付ける（Ctrl/Cmd+V）ことをお勧めします。そうすることで、Jiraカードは新しい値を表示し、自動的に更新されます。

**ボードをMiroの別のチームに移動した場合、ボード上のJiraカードはどうなりますか？**

Jiraカードはボードに残りますが、誰も変更することはできません（移動先のチームに同じJiraインスタンスが設定されている場合でも）。

カードをクリックすると、*「JIRA カードが別のアカウントからインポートされました」*というメッセージが表示されます。カードを編集可能にしたい場合は、ボードに再度インポートしてください。

**Jira カード インテグレーションに追加費用はかかりますか？**

Jira カードはすべての有料プランと Education プランで追加費用なく利用できます（Starter、Business、Education、Enterprise プラン）。

**ボード上のすべての Jira カードにユーザーがアクセスできますか？**

Jira カード インテグレーションに対するアクセス権限により、ユーザーはアクセス可能な Jira プロジェクト内でのみカードを作成および編集できます。

Miro のボード上のすべてのウィジェットがボードにアクセスできるすべてのユーザーに表示されるため、Jira 認証情報を持っていない場合や、適切な認証情報を持っていない場合、タイトルやその他のフィールドを含む折りたたまれた Jira カードを Miro のボードで閲覧することができますが、カードを展開して完全に確認したり変更したりすることはできません。

**アトラシアンは Jira Server のサポートを終了しましたか？**

はい、アトラシアンは 2024年2月に Jira Server のサポートを終了しています。

**Miro プランナー/Jira カードは Jira のカスタムフィールド（カスタム課題タイプとカスタム依存関係）をサポートしていますか？**

はい、どちらもサポートしています。**カスタム課題タイプ**と**カスタム依存関係**のフィールドが Jira に設定されており、*さらに* Miro プランナーがその Jira インスタンスで認証されている場合、これらのカスタムフィールドはプランナーで利用可能です。

**Miro は Jira Data Center に対して OAuth 2.0 をサポートしていますか？**

はい。詳しくは[OAuth 2.0 を使用して Jira Data Center に接続する](https://help.miro.com/hc/articles/25753304280466)をご覧ください。

**Jira カードをテーブルとタイムラインで使用する**

**Jira の課題をテーブルとタイムラインにインポートする方法は？**

Jira カードを直接テーブルまたはタイムラインにドラッグアンドドロップすることで、1つまたは複数の課題をインポートできます。これが現在の唯一の方法です。

**テーブル内のすべてのフィールドは Jira とリンクしていますか？**

いいえ、初期リリースでは、5つのフィールドのみが Jira と同期されます：

3つのシステム Jira フィールド：

- タイトル
- 説明
- 終了日（Jira では締切日として表示）

2つのカスタム Jira フィールド：

- 開始日
- 工数見積

**テーブルの同期されないフィールドは何ですか？**

担当者とステータスのフィールドは Jiraに同期されず、テーブルとタイムラインでは無効化されています。これらのフィールドとその内容は存在しますが、テーブルとタイムラインでは表示も編集もできません。

これらのフィールドは Jira カードのサイドパネルで直接編集できます。テーブルやタイムラインから行をキャンバスにドラッグするだけで、Jiraカードが再表示されます。

上記の5つのフィールド（タイトル、説明、終了日、開始日、工数見積）以外のすべてのフィールドは Miro にのみ保存され、Jira には同期されません。

**なぜサポートされている5つのJiraフィールドのいずれかをテーブルやタイムラインで編集できないのですか？**

そのフィールドが Jira の編集画面に存在しない可能性があります。

フィールドが編集画面にあるかどうかを簡単に確認する方法:

Miroで、Jiraカードのサイドパネルを開きます。サイドパネルにフィールドがあるか確認してください。フィールドが存在しない場合は、Jiraの編集画面にフィールドを追加する必要があります。

Jiraでフィールドが編集可能なのに、編集画面で表示されない場合があります。この場合、それらのフィールドはMiroでは編集できません。

編集できないフィールドが**開始日**または**見積もり**ですか？その場合:

そのフィールドがJiraに存在しないか、編集画面から欠落している可能性があります（前述のポイントを参照してください）。

開始日または見積もりには、これらがカスタムJiraフィールドであるため、マッピングの問題がある可能性があります。

これらのフィールドを次のロジックに基づいてマッピングしています:

- **開始日**: 次の名前が付けられたフィールドを確認します：Start Date 、StartDate、Target Start
- **見積もり**: 次の名前が付けられたフィールドを確認します：ストーリーポイント、ストーリーポイント見積もり、ストーリーポイント、StoryPoints、StoryPoint
- 開始日または見積もりフィールドが上記のいずれかの名前でない場合、編集がうまくいかない原因となる可能性があります。

**なぜ Miro のテーブルやタイムラインで、開始日または見積もりの編集がうまくいかないか、または Jira の誤ったフィールドが更新されるのですか？**

現在、Jira の開始日と見積もりフィールドは自動マッピングに依存しています。Jira 上でこれらはカスタムフィールドであるため、Jira の設定で複数のフィールドが上記の条件に一致する場合があります。

上記のフィールド名の順序に従って最初に一致するものを選択します。

たとえば、ある Jira チケットに Story Points フィールドと Story point estimate フィールドの両方がある場合、上記リストによれば最初に一致するのは Story Points です。したがって、テーブル内で見積もりフィールドに対する変更は、Jira の Story Points フィールドを更新し、Story point estimate ではありません。

現時点では、この問題に対する回避策はありません。この問題が発生した場合は、サポートチームにフィードバックを送信してください。これにより、より高度なフィールドマッピング機能の開発に役立てることができます。

**なぜ2つの異なるインスタンスからのJiraカードを1つのテーブルまたはタイムラインにインポートできないのですか？**

現在、1つのテーブル/タイムラインごとに1つのJiraインスタンスのみをサポートしています。テーブル/タイムラインにJiraカードがインポートされると、そのテーブル/タイムラインはその特定のJiraインスタンスにリンクされます。

たとえすべてのJiraレコードが削除されたとしても、元のJiraインスタンスへのリンクは残ります。別のJiraインスタンスからカードをインポートするには、新しいテーブル/タイムラインを作成する必要があります。

**なぜテーブルやタイムラインで私のJiraレコードのステータスフィールドや担当者フィールドが見えない、または編集できないのですか？**

現在、Jiraのステータスフィールドと担当者フィールドはテーブルやタイムラインではサポートされていません。これらのフィールドをテーブルやタイムラインで無効化することを決定しました。これは期待を管理し、混乱やデータ損失を避けるためです。Jiraのステータスフィールドと担当者フィールドとその内容は存在しますが、テーブルやタイムラインには表示されません。

これらのフィールドは、Jira カードのサイドパネルで直接編集できます。テーブルまたはタイムラインから行をキャンバスにドラッグすることで、Jira カードを再表示させることができます。
