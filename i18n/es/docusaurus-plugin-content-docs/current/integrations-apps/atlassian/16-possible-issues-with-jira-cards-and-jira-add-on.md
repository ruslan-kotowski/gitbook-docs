| Usas un proxy / Tus URL de Jira externas e internas no coinciden.  Asegúrate de completar el campo**Jira URL** con la dirección a la que podamos acceder, por lo que por favor configura un proxy inverso que nos permita el acceso y/o sigue los pasos de esta [guía de Atlassian](https://confluence.atlassian.com/jirakb/configure-jira-server-to-run-behind-a-nginx-reverse-proxy-426115340.html). Con esta solución, la integración podrá conectarse y remitir solicitudes de manera exitosa entre tu Jira y Miro si tus URL externas e internas son diferentes.   También podrías querer [prolongar el valor del tiempo de espera en tu servidor proxy.](https://help.miro.com/hc/articles/360017572694-Add-Miro-to-Allowed-Domains)  La lista de endpoints se puede encontrar aquí: [Preguntas frecuentes sobre tarjetas de Jira](https://help.miro.com/hc/articles/360013463739-Jira-Cards-FAQ) |
| Hay una incidencia con tu certificado SSL (no se admiten certificados autofirmados).  Comprueba el certificado SSL activo en el servidor de Jira. [Esta herramienta](https://www.ssllabs.com/ssltest/) podría ser útil: ingresa tu URL de Jira y verás los resultados de la comprobación de conexión.  Ejemplo: el certificado puede ser correcto (el **Certificado**en verde), pero la cadena de certificados del servidor podría estar incompleta (**intercambio de claves** en amarillo), por lo tanto, nuestro sistema obtiene una respuesta de que es necesario actualizar el certificado.  Consulta [este sitio](https://whatsmychaincert.com/) para resolver problemas. |
| Tu Jira está bajo inicio de sesión único (también puede generar el error **"La autenticación entrante no está configurada correctamente"**).  Asegúrate de que tu proceso de inicio de sesión único no se aplique a las solicitudes de conexión de nuestra integración. Para lograrlo, se deben excluir los siguientes puntos finales de los procesos de inicio de sesión único:   ``` GET \{JIRA_URL\}/rest/api/2/serverInfo (OAuth 1.0) POST \{JIRA_URL\}/plugins/servlet/oauth/request-token (OAuth 1.0) POST \{JIRA_URL\}/plugins/servlet/oauth/access-token (OAuth 2.0) POST \{JIRA_URL\}/plugins/servlet/oauth2/* ``` |
| Comportamiento inesperado durante la instalación | Usas las versiones de Jira 6.4 o anteriores.  Nuestras tarjetas no funcionarán con estas versiones debido a [este error de Jira](https://jira.atlassian.com/browse/JRASERVER-42811). Actualiza tu Jira a la versión más reciente. |

| **Incapacidad para autorizar en Jira a través de Miro.  Error: excepciones  (ejemplo: io.netty.handler.timeout.ReadTimeoutException)** | Esto puede ocurrir debido a una configuración incorrecta de la infraestructura de Jira cuando esta configuración indica que es compatible con el protocolo HTTP/2, pero no se realiza ninguna transferencia de datos al intentar usarlo. Revisa tu configuración de HTTP/2 en los archivos de configuración de tu servidor web para corroborar que estén configurados correctamente.  Si es necesario, deshabilita temporalmente el soporte HTTP/2 en la configuración de tu servidor para garantizar la compatibilidad con versiones anteriores y el servicio ininterrumpido hasta que se resuelva la incidencia. |

También, consulta [Cómo configurar un WebHook para tarjetas de Jira.](https://help.miro.com/hc/articles/360017731113-How-to-Set-Up-WebHook-for-Jira-Cards?source=answerbot) |

| **No has iniciado sesión y no tienes los permisos necesarios para actuar sobre la incidencia seleccionada como invitado. Por favor, inicia sesión** | Desafortunadamente, debido a que nuestro complemento usa cookies, Jira no te permitirá iniciar sesión desde esta página.  Inicia sesión en Jira en otra pestaña del navegador. |
| Después de hacer clic en el botón **Instalar** en la página del complemento, podrías ver el siguiente error:  hiccup.png | Una pérdida momentánea de la conexión.  En este caso, simplemente vuelve a intentar instalar un minuto más tarde. |
| Durante la configuración del Complemento de Jira o después de ella, no puedes pasar a la página siguiente en un paso | Algo en tus cookies o la caché detiene el proceso.  Borra la memoria de tu navegador para el dominio *atlassian.com* e intenta de nuevo. |
| Después de una instalación exitosa, tus usuarios de Jira que *no* están registrados en Miro ven el menú de inicio de sesión de Miro en lugar del tablero adjunto. | Las políticas de Jira bloquean algunas de las funciones del plugin.  Lamentablemente, este comportamiento está causado por la actualización más reciente de la API de Jira y no se puede modificar en este momento. |
| El complemento no recuerda tu autorización y sigue pidiendo que inicies sesión cada vez.  Cuando intentas agregar tableros a una incidencia de Jira, aparece un selector de tableros que muestra el error "Lo sentimos, la integración no está disponible". | Las cookies de terceros están bloqueadas en tu navegador. Esto sucede principalmente con Mozilla y Safari debido a sus nuevas políticas de seguridad. Para Safari, [esta solución](https://support.apple.com/en-ke/guide/safari/sfri40732/12.0/mac/10.14) también puede ayudar. |
